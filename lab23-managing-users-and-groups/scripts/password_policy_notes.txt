Lab 23 – Managing Users and Groups
Password Policy & Security Notes

------------------------------------------------------------
1. Password Aging Configuration (Per User)
------------------------------------------------------------

Command Used:
chage -M 90 john
chage -m 7 john
chage -W 7 john

Explanation:
-M 90  → Maximum password age = 90 days
-m 7   → Minimum days between password changes = 7
-W 7   → Warning period before expiration = 7 days

Verification:
chage -l john

This displays:
- Last password change
- Expiration date
- Inactivity period
- Minimum/Maximum days
- Warning days

------------------------------------------------------------
2. Force Password Change at Next Login
------------------------------------------------------------

Command Used:
chage -d 0 jsmith

Effect:
Forces password reset upon next login.
User must change password immediately.

Verification:
chage -l jsmith

Expected Output:
Last password change : password must be changed

------------------------------------------------------------
3. System-Wide Password Defaults
------------------------------------------------------------

File:
 /etc/login.defs

Relevant Parameters:
UID_MIN
GID_MIN
PASS_MAX_DAYS
PASS_MIN_DAYS
PASS_WARN_AGE

Example:
PASS_MAX_DAYS 99999

Organizations typically reduce this to:
PASS_MAX_DAYS 90
PASS_MIN_DAYS 7
PASS_WARN_AGE 7

------------------------------------------------------------
4. Account Locking
------------------------------------------------------------

Command:
usermod -L username

Effect:
Adds "!" in /etc/shadow password field.
Prevents password-based login.

Unlock:
usermod -U username

------------------------------------------------------------
5. Disable Interactive Login for Service Accounts
------------------------------------------------------------

Command:
usermod -s /sbin/nologin username

Used for:
- Web server users
- Database users
- Background service accounts

Prevents interactive shell access.

------------------------------------------------------------
6. Security Best Practices Learned
------------------------------------------------------------

✔ Use strong password policies
✔ Lock unused accounts
✔ Use system users for services
✔ Avoid giving login shell to service accounts
✔ Regularly review /etc/passwd and /etc/group
✔ Use groups instead of assigning permissions individually
✔ Apply setgid on shared directories for collaboration

------------------------------------------------------------
7. Critical Configuration Files
------------------------------------------------------------

/etc/passwd  → User account information
/etc/shadow  → Encrypted password data
/etc/group   → Group definitions
/etc/gshadow → Secure group password info

------------------------------------------------------------
8. Principle of Least Privilege
------------------------------------------------------------

Users should:
- Have minimal required permissions
- Be added only to necessary groups
- Avoid root access unless absolutely required
